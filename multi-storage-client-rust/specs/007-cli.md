# 007: Command-line interface

- Status: Draft for review
- Depends on: 002, 003, 006

## Summary

The `msc` binary is a first-class consumer of the async Rust library. It offers
configuration validation, listing, deletion, and synchronization without
duplicating storage logic. Its arguments, streams, prompts, and exit codes are
stable contracts suitable for both humans and scripts.

## Command tree

```text
msc [--config FILE] [--version] [--help]
├── help [COMMAND]
├── config
│   └── validate [--format yaml|json] [--config-file FILE]
├── ls [OPTIONS] PATH
├── rm [OPTIONS] PATH
└── sync [OPTIONS] SOURCE
```

Explorer, MCP server, Ray, and `msc-benchmark` are excluded. Future commands
must not silently appear behind unrelated provider features.

Global `--config FILE` selects one explicit MSC file for every command.
`config validate --config-file` is a compatibility alias and conflicts with a
different global value.

## Runtime and library boundary

`main` owns a multi-thread Tokio runtime. It:

- parses and validates all argument relationships before provider I/O;
- loads config and resolves URLs;
- converts Ctrl-C into a cancellation token;
- renders progress/events from library operations;
- initializes one owned metrics SDK from `opentelemetry.metrics` when present
  and shares its meter across provider instances;
- flushes metadata/background services and shuts down owned telemetry with a
  bounded timeout before exit; and
- maps typed errors to messages and exit codes.

The library never calls `exit`, prompts, or prints. CLI rendering must not hold
transfer permits or block async executor workers.

Telemetry lifecycle follows 011. Console metrics go to stderr, never command
data on stdout. Export/flush failures produce redacted, rate-limited diagnostics
without replacing the storage result or exit code. A borrowed application SDK
is never shut down by MSC.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success, help/version, no listing matches, or user cancels a prompt |
| 1 | Config, provider, I/O, sync, or validation failure after parsing |
| 2 | CLI syntax/argument relationship error |
| 130 | Interrupted by SIGINT/Ctrl-C after graceful cancellation |

Broken pipe while writing normal stdout is treated as successful termination
when no storage mutation failed.

## Output rules

- Command data goes to stdout.
- Diagnostics, warnings, progress, and errors go to stderr.
- Non-TTY stderr disables dynamic progress automatically.
- `--quiet` suppresses normal mutation messages, not errors.
- `--only-show-errors` suppresses warnings and normal messages where supported.
- Debug output never includes credentials or unresolved secret values.
- No command depends on ANSI color for meaning.

Machine-readable global JSON output is a follow-up. YAML/JSON config validation
and dry-run JSONL are stable formats in the MVP.

## `msc help`

`msc --help`, `msc help`, and `msc help <command>` are supported. Unknown
commands or missing required subcommands return 2 and print concise usage to
stderr. `msc --version` prints the package version and returns 0.

## `msc config validate`

```text
msc config validate
  [--format yaml|json]
  [--config-file FILE]
```

It discovers, includes, expands, merges, and validates configuration, then
prints the resolved redacted configuration. YAML is the default; output order
is deterministic and suitable for golden tests. Provider construction and
network credential calls are not required merely to validate syntax, though
provider-specific options are decoded.

Telemetry settings are validated and redacted without creating an SDK,
starting a reader, or contacting an exporter endpoint.

Errors identify the source file and field path and return 1. Secrets remain
redacted in both success and error output.

## `msc ls`

```text
msc ls PATH
  [--recursive]
  [--human-readable]
  [--summarize]
  [--limit N]
  [--show-attributes]
  [-e|--attribute-filter-expression EXPR]
  [--include GLOB]...
  [--exclude GLOB]...
  [--debug]
```

`PATH` is an MSC URL or absolute POSIX path. Include/exclude flags retain command
line order and use the shared selection semantics from spec 006. `--limit` must
be positive and stops consuming the listing stream as soon as satisfied.

Default human output matches Python's bordered table with `Last Modified`,
`Size`, and `Name` headers. Size is right-aligned; other columns are left-aligned
and wrap at 100 columns. Names are relative to listed directories, and directory
names end with `/`. An exact file path retains the resolved path as in Python.
Human sizes divide by 1024 and use `B`, `KB`, `MB`, `GB`, `TB`, and `PB` labels,
rounded to one decimal place. Requested `Attributes` cells contain stable JSON
with Python-style spacing and ASCII escapes; empty attributes leave a blank cell.
Rows may be spooled to calculate widths while keeping memory bounded.
Empty results print `No files found matching the specified criteria.` and
return 0 without a summary. A reached limit prints `(Output limited to N results)`.
`--summarize` prints `Summary:`, `Total Objects:`, and `Total Size:` after the
table. Counts and sizes reflect displayed/consumed objects.

Attribute expressions are accepted only after a grammar exists and the
selected metadata provider advertises support. Otherwise the command returns a
clear unsupported error instead of approximating the filter.

## `msc rm`

```text
msc rm PATH
  [-r|--recursive]
  [-y|--yes]
  [--dry-run|--dryrun]
  [--quiet]
  [--only-show-errors]
  [--debug]
```

A directory/prefix requires `--recursive`. Without `--yes`, an actual deletion
prompts on a TTY and defaults to no. When stdin is not a TTY, the command
refuses to prompt and returns 2 with instructions to use `--yes`.

Dry-run lists exactly the objects that would be deleted and never prompts or
mutates storage/metadata/cache. Recursive delete uses the client contract and
invalidates all affected cache families after successful provider deletion.
Missing single objects are idempotent success.

`--quiet` and `--only-show-errors` are mutually exclusive because their overlap
is otherwise ambiguous. Debug is incompatible with both suppression modes.

## `msc sync`

Compatibility syntax:

```text
msc sync SOURCE
  [--target-url TARGET]
  [--delete-unmatched-files]
  [--include GLOB]...
  [--exclude GLOB]...
  [--no-ignore-hidden]
  [--symlink-handling follow|follow_strict|skip|preserve|preserve_strict]
  [--dry-run|--dryrun]
  [--dryrun-output-path DIR]
  [--verbose]
```

With `--target-url`, the command runs the direct sync from spec 006. Without a
target, it invokes replica sync only when spec 009 is implemented and the
source profile has replicas. Otherwise it returns 1; no-replica is not reported
as success.

Replica follow-up flags:

```text
  [--replica-indices 0,1]
```

Validation occurs before listing:

- `--replica-indices` and `--target-url` are mutually exclusive;
- indices are non-negative, unique, and in range;
- `--dryrun-output-path` requires dry-run;
- replica dry-run must be implemented or rejected, never ignored;
- source and target URLs must fully resolve;
- removed `--ray-cluster` is an unknown argument; and
- overlapping same-backend roots are rejected by the library.

Progress is rendered on stderr only for a TTY and is throttled. Default success
does not emit a prose report to stdout, preserving script compatibility.
`--verbose` prints start and final typed counts without changing log level.
Dry-run prints counts plus both JSONL paths to stdout.

On item failure, stderr prints a concise summary and partial counts, with a
bounded sample of failed keys. The full typed failure remains available to Rust
library callers. Ctrl-C cancels planning/work, waits for in-flight tasks and
metadata flush, then returns 130.

## Logging and debug

Normal errors are concise. An environment-controlled or future global verbosity
option may expose structured tracing, but `--verbose` retains its sync-specific
human summary meaning for compatibility. Any backtrace is opt-in and redacted.

## Intentional differences from Python

- One global config selector works for all commands.
- Invalid relationships are parser errors instead of silently ignored flags.
- Negative/out-of-range replica indices are rejected.
- Missing replicas are an error.
- Non-TTY destructive commands require `--yes`.
- SIGINT has a defined graceful exit code.
- Explorer, MCP, Ray, and benchmark entrypoints are absent.

## Acceptance criteria

- Golden tests cover every top-level/subcommand help page and version.
- Parser tests assert exit 2, usage stream, and message for unknown/missing/
  conflicting arguments.
- `config validate` golden YAML/JSON is deterministic and redacts secrets.
- `ls` tests cover empty, recursive, human size, limit, summary, attributes,
  ordered patterns, broken pipe, and listing failure.
- `rm` tests cover yes/no/EOF/non-TTY, recursive guard, dry-run, quiet modes,
  idempotent missing target, partial batch failure, and cache invalidation.
- `sync` tests cover every flag, invalid combination, TTY/non-TTY progress,
  dry-run paths, partial failure, and Ctrl-C exit 130.
- All stdout/stderr assertions are explicit; no test passes only by inspecting
  a combined stream.
- Test secrets do not occur in either output stream, panic messages, or debug
  snapshots.
- Metrics-enabled commands share one SDK; successful exit, provider failure,
  and Ctrl-C all attempt bounded telemetry shutdown. Exporter failure does not
  change the command result, and validation starts no exporter.
