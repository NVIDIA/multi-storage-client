## Bug Fixes
- GCS uploads and downloads now always remove their staging temp file when the transfer fails. Previously every failed attempt leaked the file, which for downloads to a path is created in the destination directory: a partial file for interrupted transfers, or at least `multipart_threshold` bytes for a failed multipart upload.
- Compare normalized paths in the `sync_from` overlap check, so `/data` vs `data/sub` on the same profile is rejected.
- S3 and OCI listings with `include_directories=True` and `end_at` no longer drop in-range objects when the same page also contains a directory prefix that sorts after `end_at`.
- Parallel recursive listing no longer issues a duplicate LIST request for a prefix that was fetched directly while still queued for prefetching.
- `download_file` now hands the resolved symlink target's metadata to the provider (instead of the zero-length symlink marker's), so large targets use multipart downloads and READ metrics report the real size; it also no longer issues two HEAD requests when no metadata is supplied.
- `sync` / `sync_from` with `delete_unmatched_files=True` now reports the correct target key for pruned objects in subdirectories. When the target has a metadata provider (e.g. manifest), the sync previously failed with `SyncError: Object ... does not exist` and, in multi-process mode, committed a manifest that still listed the deleted objects.
- HuggingFace `info()` and `list()` report the last commit date as `last_modified` again instead of always returning the epoch sentinel.
- A multi-process `sync` that stops early on an error (fast-fail) no longer hangs the Python process at exit while flushing unconsumed work batches.
- Report `delete_many` failures from sync DELETE batches on the error queue (previously the exception killed the worker thread and the sync reported success).
- Full-file `read(path, byte_range=Range(0, size))` calls with caching enabled now serve repeat reads from the cache instead of re-downloading and re-caching the whole object every time.
- `open(path, "r", encoding=...)` with caching enabled now honors the requested mode and encoding when the object is served from the cache; the cache-first fast path previously opened the cached file in binary mode (so `read()` returned `bytes`), and cached text opens ignored a non-default `encoding`.
- Stop counting pattern-excluded files that exist on both sides with differing metadata as sync work units; they inflated the progress-bar total and `SyncResult.total_work_units`.
- Cache access-time updates no longer raise when the cached file was concurrently evicted or is owned by another user, and they operate on an open file descriptor so a concurrently recreated cache file is never chmod'ed by mistake; the permission restore in the `finally` block previously re-raised the error the method was meant to swallow.
- Return copies from `list(..., include_url_prefix=True)` and the single-file path of `list()` instead of rewriting the key of `ObjectMetadata` objects owned by the metadata provider; a single `msc.list()` previously corrupted the in-memory manifest keys.
- HuggingFace listings now raise `FileNotFoundError` for a missing repository or revision instead of silently returning no objects; only a missing directory yields an empty listing.
